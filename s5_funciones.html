Objetivo de la sesión

Hasta ahora, cada programa que has escrito ha sido una lista lineal de instrucciones. Si dentro de un programa había un cálculo que se repetía varias veces (por ejemplo, sumar dos resistencias en serie), tenías que copiar y pegar las mismas líneas en distintos sitios. Hoy aprendes a empaquetar ese cálculo bajo un nombre — una función — y a llamarlo tantas veces como haga falta.

Al terminar la sesión sabrás:

  • Definir una función con def, parámetros y return.
  • Distinguir entre parámetros (lo que la función pide) y argumentos (lo que tú le pasas al llamarla).
  • Entender qué es una variable local y por qué no puedes usarla fuera de la función.
  • Escribir una pequeña biblioteca de funciones eléctricas y reutilizarla en varios problemas.

Esta es la sesión más importante del curso desde el punto de vista del pensamiento computacional. A partir de aquí dejas de programar como un principiante.

El problema base es eléctrico puro: construir una biblioteca con Rserie(R1, R2) y Rparalelo(R1, R2) y usarla para resolver dos circuitos sencillos. La extensión: calcular la resistencia equivalente de un circuito mixto serie-paralelo descomponiéndolo en pasos.

Recordatorio: el bucle del programador

NotaA partir de hoy, programar es descomponer

El método de las cuatro fases (analizar → pseudocódigo → código → trazar) sigue valiendo, pero la fase de análisis cambia: ya no se trata solo de identificar entrada–proceso–salida, sino también de detectar qué cálculos se repiten o son lo bastante independientes como para merecer una función propia.

Una buena función hace una cosa, y solo una, tiene un nombre que dice qué cosa hace, y se puede leer sin necesidad de mirar las otras funciones del programa.

Concepto 1 — ¿Por qué necesitamos funciones?

Imagina que en un problema necesitas calcular la resistencia equivalente de tres pares distintos de resistencias en serie. Sin funciones, escribirías esto:

Req_1 = 100 + 220
print("Req 1:", Req_1)

Req_2 = 470 + 1000
print("Req 2:", Req_2)

Req_3 = 220 + 330
print("Req 3:", Req_3)

Tres veces casi la misma línea. Y si mañana el problema fuera de resistencias en paralelo, tendrías que reescribir las tres con la fórmula (R1·R2)/(R1+R2), con el riesgo de equivocarte en una y no en las otras.

Con una función, el cálculo se escribe una vez y luego se llama tres:

def Rserie(R1, R2):
    return R1 + R2

print("Req 1:", Rserie(100, 220))
print("Req 2:", Rserie(470, 1000))
print("Req 3:", Rserie(220, 330))

Tres ventajas inmediatas:

  1. No te repites. Si la fórmula cambia, la cambias en un solo sitio.
  2. El programa principal se lee solo. Rserie(100, 220) dice exactamente lo que hace; 100 + 220 solo si recuerdas el contexto.
  3. Las funciones se pueden combinar. Rserie(Rparalelo(220, 330), 100) es legal y resuelve un circuito mixto en una línea.

Concepto 2 — Sintaxis: def, parámetros, return

La sintaxis general:

def nombre_de_la_funcion(parametro1, parametro2):
    # cuerpo de la función
    return valor_de_salida

Cuatro elementos:

  • def es la palabra reservada que define una función. Va seguida del nombre que tú elijas.
  • Entre paréntesis van los parámetros: las variables locales que la función va a recibir cuando se la llame.
  • Tras los dos puntos, indentado, va el cuerpo (igual que en if o for).
  • return indica qué devuelve la función al exterior. La línea con return también termina la ejecución de la función.

Ejemplo mínimo:

def cuadrado(x):
    return x * x

print(cuadrado(5))    # 25
print(cuadrado(7))    # 49
print(cuadrado(0.1))  # 0.010000000000000002
ImportanteDefinir ≠ llamar

def cuadrado(x): solo define la función. Hasta que no escribas algo como cuadrado(5), la función no se ejecuta. Es muy típico al empezar definir bien la función, ejecutar el programa y no ver nada por consola — porque te ha faltado llamarla.

TipConvenciones de nombre
  • Funciones que devuelven un cálculo numérico: nombre con minúsculas y guiones bajos (area_circulo, velocidad_final) o, si son nombres técnicos consolidados, respeta la mayúscula del símbolo (Rserie, Rparalelo, Vrms).
  • Funciones que devuelven un sí/no: empieza por es_ (es_par(n), es_aprobado(nota)).
  • Evita nombres genéricos como funcion1 o f. El nombre tiene que decir qué hace.

Concepto 3 — Parámetros y argumentos

Es un matiz de vocabulario que conviene tener claro:

  • Parámetros son las variables que aparecen en la definición: def Rserie(R1, R2): tiene parámetros R1 y R2.
  • Argumentos son los valores que pasas al llamar: Rserie(100, 220) pasa los argumentos 100 y 220.

El orden importa. En Rserie(100, 220), dentro de la función R1 = 100 y R2 = 220. Si llamas Rserie(220, 100), ahora R1 = 220 y R2 = 100. Para Rserie es indiferente (sumar es conmutativo), pero para una función como dividir(a, b) el orden es crítico.

Concepto 4 — return y variables locales

Mira este programa:

def doble(x):
    resultado = x * 2
    return resultado

y = doble(5)
print(y)

Salida: 10. Pero ahora prueba a poner, debajo del print(y), esta línea:

print(resultado)

Falla con NameError: name 'resultado' is not defined. ¿Por qué? Porque resultado es una variable local de la función doble: existe solo mientras la función se está ejecutando y desaparece en cuanto se termina. El programa principal nunca la ve.

ImportanteLa función habla con el exterior solo a través del return

Lo que la función calcula internamente vive y muere dentro de ella. La única forma de sacar un valor de la función para usarlo fuera es escribirlo después de return. Si la función no tiene return, devuelve None (un valor especial que significa “nada”).

Una función puede tener varios return, normalmente dentro de un if:

def signo(x):
    if x > 0:
        return "positivo"
    elif x < 0:
        return "negativo"
    else:
        return "cero"

La función se sale en cuanto encuentra el primer return que se ejecute.

Concepto 5 — El docstring

Justo después de la línea def, puedes escribir una cadena entre triples comillas que documenta lo que hace la función. Se llama docstring y es la forma estándar de Python de explicar una función a quien la lee (o a ti mismo dentro de tres meses).

def Rparalelo(R1, R2):
    """Devuelve la resistencia equivalente de R1 y R2 en paralelo (en ohmios).

    Espera R1 > 0 y R2 > 0.
    """
    return (R1 * R2) / (R1 + R2)

No es obligatorio para que la función funcione, pero a partir de S5 lo vamos a usar siempre en cualquier función con un mínimo de entidad. En las prácticas de hoy lo verás aplicado.

Práctica 1 — Biblioteca de funciones eléctricas

NotaPestaña: s5_p1_biblioteca.py

En online-python, abre una pestaña nueva con + y renómbrala s5_p1_biblioteca.py. Todo el código de esta práctica va en esa pestaña.

Vas a escribir una biblioteca con tres funciones eléctricas básicas, y luego la usarás para resolver dos circuitos sencillos en el mismo programa.

Paso 1 — Las funciones que necesitas

Función Qué hace Fórmula
Rserie(R1, R2) Resistencia equivalente de R1 y R2 en serie R1 + R2
Rparalelo(R1, R2) Resistencia equivalente de R1 y R2 en paralelo (R1·R2) / (R1 + R2)
intensidad(V, R) Intensidad por la ley de Ohm V / R

Paso 2 — Pseudocódigo del programa principal

definir Rserie(R1, R2) que devuelve R1 + R2
definir Rparalelo(R1, R2) que devuelve (R1·R2) / (R1 + R2)
definir intensidad(V, R) que devuelve V / R

circuito A: dos resistencias en serie
  Req_A = Rserie(100, 220)
  I_A = intensidad(12, Req_A)
  imprimir resultados

circuito B: dos resistencias en paralelo
  Req_B = Rparalelo(220, 330)
  I_B = intensidad(12, Req_B)
  imprimir resultados

Los dos circuitos están alimentados con 12 V. El alumno tiene que calcular tanto la Req como la intensidad total I.

Paso 3 — Código Python

Escríbelo línea a línea, no copies y pegues.

# Biblioteca eléctrica básica
# S5 · Funciones — TECI I

def Rserie(R1, R2):
    """Devuelve la resistencia equivalente de R1 y R2 en serie (ohmios)."""
    return R1 + R2

def Rparalelo(R1, R2):
    """Devuelve la resistencia equivalente de R1 y R2 en paralelo (ohmios).

    Espera R1 > 0 y R2 > 0.
    """
    return (R1 * R2) / (R1 + R2)

def intensidad(V, R):
    """Devuelve la intensidad que circula por R con tensión V, por la ley de Ohm (A)."""
    return V / R


# Programa principal: dos circuitos a 12 V

V = 12

# Circuito A: 100 Ω en serie con 220 Ω
Req_A = Rserie(100, 220)
I_A = intensidad(V, Req_A)
print("Circuito A (serie):")
print("  Req =", Req_A, "ohmios")
print("  I   =", I_A, "amperios")

# Circuito B: 220 Ω en paralelo con 330 Ω
Req_B = Rparalelo(220, 330)
I_B = intensidad(V, Req_B)
print("Circuito B (paralelo):")
print("  Req =", Req_B, "ohmios")
print("  I   =", I_B, "amperios")

Paso 4 — Trazado y validación

Antes de ejecutar, completa tú los valores esperados a mano:

Circuito Req esperada I esperada
A (serie) 100 + 220 = 320 Ω 12 / 320 = 0.0375 A
B (paralelo) (220·330)/(220+330) = 132 Ω 12 / 132 ≈ 0.0909 A

Si tu programa imprime estos números (con muchos decimales de cola en el caso B, no importa), está bien.

Paso 5 — Reutiliza la biblioteca

Sin tocar las funciones, añade al final del programa el cálculo de un tercer circuito a tu elección (por ejemplo, R1 = 470 Ω y R2 = 680 Ω en serie a 9 V). Comprueba que con tres líneas adicionales lo resuelves: Req, I, e impresión.

Ahí está el sentido de las funciones: si no las tuvieras, tendrías que repetir las fórmulas cada vez.

TipLo que pasa si te falta el return

Quita por un momento el return de Rserie (déjala con la línea R1 + R2 solita, sin return delante). Ejecuta el programa. Verás que Req_A imprime None y que I_A falla con un error tipo unsupported operand type(s) for /: 'int' and 'NoneType'.

Ese error misterioso significa: “estás intentando dividir entre algo que es None, no un número”. Y la causa es siempre la misma: una función que debía devolver algo y no devuelve nada. Vuelve a poner el return y todo funciona.

Práctica 2 (extensión) — Circuito mixto en pasos

NotaPestaña: s5_p2_circuito_mixto.py

Solo si has terminado la práctica 1. Abre otra pestaña con + y renómbrala s5_p2_circuito_mixto.py. Copia primero la biblioteca de la práctica 1 al inicio — es lo que vamos a reutilizar.

Considera el siguiente circuito a 12 V:

Interpretación: R1 en serie con la asociación en paralelo de R2 y R3.

La técnica estándar para resolverlo a mano es descomponer en pasos:

  1. Calcular la resistencia equivalente del paralelo de R2 y R3 → Rp.
  2. Calcular la resistencia equivalente total como R1 en serie con Rp → Req.
  3. Calcular la intensidad total con la ley de Ohm a partir de Req y V.

La gracia del ejercicio es que los tres pasos se traducen literalmente a tres llamadas de función.

SoluciónSolución (clic para desplegar) 
# Resistencia equivalente de un circuito mixto serie-paralelo
# S5 · Funciones — TECI I (extensión)

def Rserie(R1, R2):
    """Devuelve la resistencia equivalente de R1 y R2 en serie (ohmios)."""
    return R1 + R2

def Rparalelo(R1, R2):
    """Devuelve la resistencia equivalente de R1 y R2 en paralelo (ohmios).

    Espera R1 > 0 y R2 > 0.
    """
    return (R1 * R2) / (R1 + R2)

def intensidad(V, R):
    """Devuelve la intensidad por la ley de Ohm (A)."""
    return V / R


# Datos del circuito
V  = 12
R1 = 100
R2 = 220
R3 = 330

# Paso 1: paralelo de R2 y R3
Rp = Rparalelo(R2, R3)
print("Paso 1 — Rp =", Rp, "Ω")

# Paso 2: R1 en serie con Rp
Req = Rserie(R1, Rp)
print("Paso 2 — Req =", Req, "Ω")

# Paso 3: intensidad total
I = intensidad(V, Req)
print("Paso 3 — I =", I, "A")

Resultados esperados:

  • Rp = (220·330)/(220+330) = 132 Ω.
  • Req = 100 + 132 = 232 Ω.
  • I = 12 / 232 ≈ 0.0517 A (unos 51.7 mA).

El truco de las funciones: una vez tienes Rserie y Rparalelo definidas, los tres pasos del cálculo a mano se convierten en tres líneas de Python que se leen casi como el enunciado. Esa es la potencia de descomponer un problema en subproblemas.

Si quisieras hacerlo en una sola línea, podrías escribir directamente:

I = intensidad(V, Rserie(R1, Rparalelo(R2, R3)))

Es legal en Python, y a veces se hace, pero a costa de legibilidad: la versión en pasos es más fácil de leer, de depurar y de explicar al examen. Quédate con esa.

Cierre — Trazado en pizarra

Antes de irte, traza este fragmento — es exactamente el tipo de pregunta que entra en el examen:

def f(x, y):
    z = x + 2 * y
    return z

a = f(3, 4)
b = f(a, 1)
print(a, b)

Tabla de trazado:

Paso Variable Valor calculado
Llamada f(3, 4) x (local) 3
y (local) 4
z (local) 3 + 2·4 = 11
Vuelve al main a 11
Llamada f(a, 1) x (local) 11
y (local) 1
z (local) 11 + 2·1 = 13
Vuelve al main b 13

Salida: 11 13.

TipLo nuevo que entra en el examen con las funciones

A partir de S5, en el bloque de trazado del examen pueden aparecer funciones. El método se amplía con una columna más: cuando entras en una llamada, anota los valores que toman los parámetros locales; cuando salgas (return), anota el valor devuelto y cómo se asigna fuera.
